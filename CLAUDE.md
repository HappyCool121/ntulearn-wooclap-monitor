# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A local Node CLI (`src/cli.js`, ESM, Node ≥22, deps: only `commander` + `playwright`) that attaches to the user's already-logged-in Chrome via CDP, polls a Wooclap session embedded in an NTULearn tab, and sends question images to Telegram (a configured private chat, private /start subscribers, and every group that adds the bot). Optional `watch --suggestions` appends a `gpt-6-luna` answer generated by spawning the local Codex CLI. `README.md` is the detailed behavioral spec; `PLAN.md` tracks in-progress step plans.

## Commands

```bash
npm ci
npm run check                              # node --check on every src file (list is hard-coded in package.json — add new src files there)
npm test                                   # unit tests: node --test test/*.test.js
node --test test/groups.test.js            # single test file
node --test --test-name-pattern "setup" test/cli-setup.test.js   # single test by name
npm run test:browser                       # Chrome integration (needs installed Chrome: npx playwright install --with-deps chrome)
NTULEARN_TEST_PREVIEW=docs/example-question.jpg npm run test:browser   # regenerate preview image
node src/cli.js watch --dry-run            # run detection/capture without Telegram or Codex
```

CI (`.github/workflows/ci.yml`) runs `check` + `test` on Node 22/24 and `test:browser` on Linux. There is no linter or build step.

## Architecture

Data flow for `watch` (wired in `src/cli.js`):

1. **`BrowserSource`** (`browser.js`) finds the NTULearn tab/Wooclap frame and calls `frame.evaluate(extractDom)`. `extractDom` in `detection.js` is **serialized into the page** — it must stay self-contained (no imports/closures) and read only visible DOM, never app stores or tokens. `classifyObservation` turns the raw result into `active | waiting | results | loading | unavailable`.
2. **`Monitor.tick`** (`monitor.js`) feeds observations to `AppearanceTracker` (dedup by visible question ID, else a hash of normalized content excluding timers/counts) and `HealthTracker` (one outage notice after 60s, one recovery notice). On a new appearance it captures an image: native screenshot first, falling back to `QuestionImageRenderer` (`question-image.js`), a headless card recreated from a MathML snapshot, all under `withDeadline` limits.
3. **`DeliveryQueue`** (`telegram.js`) is a single serial worker (max 100 pending) with retries/backoff, rate-limit handling, photo→text fallback on 400, and supergroup migration via `onFailure`. Parts without `chat_id` are fanned out to every id from `destinations()` (the group registry); `isDestination` drops sends to destinations removed since queuing; private command confirmations explicitly bypass this filter so `/stop` can be confirmed.
4. **Suggestions**: on the first confirmed `onSent` receipt per question, `Monitor` enqueues one job in `CodexSuggestions` (`codex-suggestions.js`); the result is applied as caption/text edits to *every* delivered copy, keyed by `chatId:messageId` (message IDs collide across chats). The question payload is frozen at detection time so later page changes can't leak into the edit. The Codex child runs in a temp dir with a whitelisted env, its own process group, SIGTERM→SIGKILL cleanup, and the model is pinned (`constants.js`) — never fall back to another model.
5. **Groups**: `GroupRegistry`/`GroupListener` (`groups.js`) poll `getUpdates` for `my_chat_member`, group `/start@bot`, and private `/start` or `/stop`, persisting groups, private subscription preferences, and update offset atomically to `groups-<hash>.json` beside the config. `acquireBotLock` (`telegram-receiver.js`) ensures one poller per bot; existing webhooks must never be deleted.

Config lives outside the repo (`~/.config/ntulearn-wooclap-monitor/config.json`, mode 0600, env vars override); `redact()` in `config.js` must be applied to anything that might contain the bot token.

**Answer submission is intentionally disabled.** `answers.js` (`AnswerController`), `TelegramReceiver`, and browser submission helpers are kept for future work and still have tests, but `watch` must not start them or expose answer controls. Don't remove them, and don't wire them back in unless asked.

## Testing conventions

- Unit tests inject fakes via constructor options (`log`, `now`, `wait`, `telegram`, etc.) rather than mocking modules.
- CLI-level tests spawn `src/cli.js` with `node --import <preload.mjs>` where the preload replaces `globalThis.fetch` to fake the Telegram API, and put a fake `codex` executable first on `PATH`. Follow this pattern for new end-to-end scenarios; tests must never hit real Telegram, NTULearn, or Codex.
- Browser tests use isolated temporary Chrome profiles with intercepted synthetic NTULearn/Wooclap pages. All quiz content is synthetic.
- Wooclap DOM changes usually mean updating `src/detection.js`.
